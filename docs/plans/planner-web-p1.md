# Plan — planner-web P1: interview engine + deterministic parsing

Parent plan: [planner-web.md](planner-web.md). Raw task graph:
[planner-web-p1-task-graph.json](planner-web-p1-task-graph.json) — that JSON holds the
authoritative per-task scope and verification text; read it, not this file, when executing.

## Objective

P0 built the skeleton: schema, store with tiered provenance, naming and validation engines,
the single-file build, the shell, persistence, and a working name-builder screen. It is a
form.

P1 makes it an **interview**. A researcher pastes a paragraph describing what they did, the
app extracts what it deterministically can, asks the smallest set of questions needed to
fill the rest, expands the design into concrete condition rows with sample IDs, and renders
the resulting filenames — **with the LLM switched off entirely**.

**Demoable outcome:** paragraph → questions → sample IDs → filenames.

C1-6 is deliberately alone and last. Repo lesson 4 is unambiguous that the UI-wiring task is
the one that fails: across P0, every single-module task landed first try while the two
`app_streamlit.py`-shaped wiring tasks took the only retry and produced both post-verify
defects.

## Decisions made in this plan

**The marker KB is generated, never retyped.** `markers.py` holds 90 canonical markers, their
aliases, and — critically — `AMBIGUOUS_IN_FREE_TEXT`, a list of aliases (`snap`, `halo`,
`clip`, `venus`, `citrine`, `emerald`, `cerulean`, `tomato`) that are real marker spellings
*and* ordinary English words. That list was derived painfully and is the difference between
"we took a snap of the halo around the tomato explant" yielding nothing and it yielding three
bogus fluorophores. Per lesson 40, any constant that must mirror a producer's output has to be
**generated by running the producer**; so `tools/export_markers_kb.py` emits
`web/kb/markers.json`, and a pytest regenerates and byte-diffs it so an un-exported `markers.py`
edit fails the Python gate instead of silently shipping a stale table.

**K-1 is discharged by C1-1.** The parent plan listed "seed ~90 fluorophore identities" as a
user-owned content task with a decision prerequisite: ~12 entries are *families* spanning
several spectra (MITOTRACKER, LYSOTRACKER, SYTOX, GCAMP, BODIPY), and HALO/SNAP/CLIP are
*tags* while PHALLOIDIN/WGA are *targeting moieties* — none of which has a spectrum of its own.
Rather than block on content authoring, C1-1 bakes `isFamily`/`variants[]` and
`class` into the generated KB schema now, so the P2 panel engine cannot silently accept a
channel with no spectrum. What remains user-owned is per-marker **spectra** (K-2), not the
identity list.

**The predicate DSL must be total, not correct-on-good-input.** It evaluates author-written
JSON, so every malformed input — unknown operator, missing path, wrong arity, bad regex,
40-deep nesting — returns `false` rather than throwing. A bad KB rule must degrade to "that
question isn't asked", never to a white screen. Its `matches` operator routes through C0-4's
`compileFullMatch`, so the Python/JS anchoring landmine cannot reappear in a second place.

**Nothing the machine infers is ever STRONG.** Free-text proposals are tagged `freetext`
(WEAK); the interview writes the question's tag; only a human answer is `user`. C0-2's
`canOverwrite` then makes it *structurally* impossible for a re-parse to clobber something the
user typed. Proposals are also **reviewable, never auto-applied** — this project shipped a
silent-auto-apply defect once already (T10), and the fix is that a proposal is a suggestion
with visible evidence until a human accepts it.

**Two engines that must not diverge.** Sample IDs and filename tokens both flow through
`engine/naming.js` `sanitizeToken`; C1-5 reuses it rather than writing a second sanitizer, and
its test compares against a live `sanitizeToken` call rather than a hardcoded string.

## Risks

**The free-text port is the defect-prone one.** `metadata.py::_extract_markers` uses
`re.finditer` (not `re.search`) with word-boundary matching and longest-match-wins overlap
resolution. This repo has already shipped the exact bug that comes from getting it wrong:
one-match-per-alias silently dropped a real second fluorophore depending on channel order
(`ATTO 647-N` + `ATTO 647`). C1-4's scope therefore says *read the Python first, do not
re-derive*, and its verification runs the real Python extractor over shared fixture paragraphs
and compares canonical **sets** (marker order is not stable — lesson E3).

**Question fatigue.** Forty questions at a microscope is a tool nobody opens twice. Every
question is skippable, `nextQuestions` takes a hard `limit`, and a slot already filled from
free text is asked as a *confirmation with a suggested default* rather than a blank retype.

**Interview/free-text composition.** These two features are only worth having together: the
parser fills WEAK slots, the interview then asks about exactly those, pre-filled. That
producer→consumer pair is named here (lesson 36) and C1-6's verification exercises it end to
end rather than trusting either side's own tests.

## Out of scope

Panel/optics/spillover and the controls engine (P2), exports and the LLM seam (P3), Pages
deploy (P4). No LLM code lands in P1 at all.
