# Plan — Microscopy experiment planner: web pivot + zero-install + naming as downstream artifact

Generated by approved plan: [i-want-to-re-jolly-wind.md](../../.claude/plans/i-want-to-re-jolly-wind.md). Raw task graph: [planner-web-task-graph.json](planner-web-task-graph.json)

## Objective

Pivot Micronaut from a metadata-driven file renamer (extracting naming fields *out of* microscopy files after acquisition) to a static, zero-install microscopy experiment **planner** that walks a researcher from design intent through panel, controls, and acquisition settings — emitting the naming convention as one downstream artifact of a finished design. The web-based planner runs from `file://` or GitHub Pages with no install, no JVM, no dask, no Streamlit, and no per-PC deployment burden.

## Why now

Two problems turn out to be **the same problem**:

1. **Reverse-engineering is fragile.** Four days of work on the extraction pipeline (`metadata.py`, `metadata_keys.py`, `field_map.py`, `key_ranking.py`) cannot catch all fields reliably because the information genuinely is not in the file in a consistent, vendor-neutral form. The user knows the answer at planning time.

2. **The venv install burden is the extraction pipeline.** The sole reason the app needs `bioio` (which drags a JVM via `bioio-bioformats`, plus dask, xarray, zarr, imagecodecs, and Streamlit's pyarrow tail) is to *extract* metadata. Delete the extraction and what remains — template rendering, regex validation, the marker dictionary, the profile schema — is ~600 lines of pure rules and data with **zero third-party dependencies**. That runs in a browser tab, from a URL or a double-clicked file, with no install anywhere.

**The move is one:** delete metadata extraction, ship a web planner, and solve the install problem forever.

## Architecture decisions

| Decision | Rationale |
|----------|-----------|
| **Delivery** | Single self-contained HTML, served from GitHub Pages *and* offered as a download. Same bytes both ways so hosted and offline cannot diverge. |
| **Framework** | None — vanilla ES modules in development, flattened to one classic script at build via a mechanical inliner. This is not aesthetic: under `file://` the origin is opaque and `<script type="module">` import resolution is CORS-blocked. |
| **LLM** | Optional, off by default. Deterministic tier (keyword spotting from `markers.py` alias matching + factor/replicate patterns) always on. Manual paste-provider ships v1. Ollama is opt-in (tier 2). The LLM **never originates a domain fact** — structured guardrail: the adapter supplies a vocabulary and drops any ID not in it. |
| **Interview** | Deterministic question bank; LLM upgrades comprehension but is not the floor. Tier 0 already carries the headline demo (paragraph → slots via existing matching). |
| **Renaming** | **NOT** in the web app. Micronaut Classic keeps the rename-folder job (destructive graph operation, transactional apply, rollback manifests, original-name ledger, lock/cloud-sync probes, case-insensitive collisions, MAX_PATH). The web planner will never rename a file. |
| **JS tests** | `node --test web/tests/*.test.js` (verified on node v22.21.0 with `node:test` built into the binary -- the bare `node --test web/tests/` form fails with `MODULE_NOT_FOUND`; use the glob, or `cd web && node --test`). Zero npm install; 3-line package.json only. Cross-language coupling: shared `regex_conformance.json` fixture read by both pytest and JS tests, since `re.fullmatch` in Python and `RegExp.test` in JS have different defaults. |

## Invariants — structural constraints that guard correctness

- `web/` never imports from `src/` — the two products share data files only (`profiles/facsi_default.json` loads unchanged into `kb/naming.profiles.json`)
- No `fetch()` in the released artifact
- No `type="module"`, dynamic `import()`, or top-level `await` in the released artifact
- Every exported symbol name is unique across `web/src/**`
- Every feature fully usable with the LLM disabled
- Every computed number carries `basis` + `inputs` (never renders as a measurement)
- The LLM may only emit IDs present in the vocabulary the app supplied
- Never write into a STRONG-provenance slot from a weaker source (tiered: STRONG ≥ user/user_edited/imported; WEAK ≥ freetext/kb-default/derived/default; PROVISIONAL ≥ llm/llm_freetext)
- Python gate: `pytest -q -m 'not integration'` stays green (Classic must not regress)
- JS gate: `node --test web/tests/*.test.js`, no `node_modules` ever created

### Content tasks — owned by the user (Daniel), not the code

These are authored in the knowledge pack (`web/kb/`) and do not change code:

- **K-1** — Seed ~90 fluorophore identities from `markers.py`
- **K-2** — Ex/em + recommended lines for top 30 dyes
- **K-3** — FACSI instruments, objectives, lines, detectors
- **K-4** — Question bank v1 (~30 questions)
- **K-5** — Control rules v1 (~15 rules)
- **K-6** — 15 golden experiments as regression fixtures
- **K-7** — Modality profiles + guidance

Content authoring is a continuing obligation and has a **decision prerequisite before K-1 can begin:**

1. ~12 of the 90 canonical fluorophores are **families, not dyes** — `MITOTRACKER` spans Red/Green/Deep Red/Orange (four spectra). Also `LYSOTRACKER`, `SYTOX`, `GCAMP`, `BODIPY`. These need `isFamily: true` + `variants[]`, and the panel engine must force disambiguation.
2. `HALO`/`SNAP`/`CLIP` are **tags**, `PHALLOIDIN`/`WGA` are **targeting moieties** — none has a spectrum. These need `class` + `requiresLigand`/`requiresConjugate` so the panel engine does not silently accept a channel with no spectrum.

## Out of scope — explicitly deferred or excluded

- Metadata extraction (the entire reason for the pivot)
- File renaming in the browser
- Multi-user or concurrent editing
- Server, authentication, authorization
- Scheduling or sample tracking
- ELN/LIMS integration
- Cloud LLM providers (tier 3, seam exists for later)

## Key risks and mitigations

**Risk: localStorage on a shared scope PC.**  
Every failure mode is silent: IT clears browsing data, Chrome shares one storage bucket across all `file://` pages (two people's plans collide), incognito loses everything, `QuotaExceededError` gets swallowed.  
**Position:** localStorage is a convenience, never the record of truth. Auto-trigger `.micronaut.json` download on completion (real `<a download>`, no API, works on `file://`); show a persistent "last exported: N changes ago" counter; keep a 5-slot autosave ring buffer; loud `try/catch` on every write.

**Risk: Interview fatigue at the bench.**  
Forty questions at a microscope is a tool nobody opens twice.  
**Mitigations:** every question skippable; the app usable outside-in (jump to any step); ≤8 questions before first useful output; choosing the instrument answers ~15 at once as WEAK-tier defaults accepted in bulk.

**Risk: Curated content ages or is wrong.**  
Certain, not merely likely.  
**Mitigations:** every record carries `curatedBy`/`curatedAt`/`confidence`/`sources`; every Experiment stamps `kbVersion` and recomputes-and-diffs on load; `basis` labelling means an estimate never renders as measurement. Plus an explicit non-goal: *"a planning aid, not a validated instrument model — verify at the scope."*

**Risk: The inliner is the riskiest component.**  
If the single-file build does not work, everything after it is built on sand.  
**Mitigation:** C0-5 is explicitly the inliner itself, run early, with hard build gates (duplicate exports, cycles, `fetch()` in release, `type="module"` in release, >2 MB size); C0-8 is a full vertical slice that **proves the built artifact actually runs from `file://`**.

**Risk: The sharpest trade-off — two test suites in two languages.**  
Writing the rules in JS means the existing ~300-test Python suite covers none of the new product, and the new engines start at zero coverage.  
**Mitigation:** Port `test_naming.py` and `test_markers.py` assertions verbatim as the first JS tests written. Pay it once, up front.
